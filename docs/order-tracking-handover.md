# Order Tracking Screen — Handover to Claude Code

Backend is fully built and tested in Supabase (project `ovwhuvkwxxlmhsldgrwo`). This doc is everything needed to build the screen — no more schema discovery required.

---

## Screen behavior, by order status × viewer role

| Status | Customer view | Agent view |
|---|---|---|
| `open` | Waiting-for-agent state. Show `point_a_address` → `point_b_address`, `price_paise`, `delivery_speed`. No agent card. | N/A — not yet accepted |
| `accepted` | Agent card: `avatar_url` (fallback to initials if null), `first_name`/`last_name`, `avg_rating_as_agent`, `completed_deliveries_count`, vehicle (from `agent_vehicles`). "Contact" button → `tel:{phone_number}`. "Open in Maps" → deep link to `point_a`. OTP shown via `get_pickup_otp()` RPC — read aloud to agent at handoff. | "Open in Maps" → `point_a`. OTP entry field → `verify_pickup_otp()`. |
| `picked_up` | "Open in Maps" → `point_b`. **Seal-check buttons (`intact`/`broken`) must be hidden/disabled until a `delivery_photos` row exists for this order** — check for it (or attempt the call and handle the specific error) before showing this UI, since `verify_delivery_seal` will hard-reject until the photo exists. | "Open in Maps" → `point_b`. Camera/upload action → `submit_delivery_photo()`. Nothing else to do here until this succeeds. |
| `delivered` | Summary view. Show seal result from `delivery_verifications`. Show a complaint banner if one exists (`complaints` where `order_id` matches). Point toward rating screen (not built yet). | Same |
| `cancelled` | Simple cancelled state, no actions | Same |

**Realtime:** subscribe to `orders` row changes filtered by `id`, so status flips (after either RPC succeeds) update the screen instantly without polling:
```js
supabase
  .channel(`order-${orderId}`)
  .on('postgres_changes',
    { event: 'UPDATE', schema: 'public', table: 'orders', filter: `id=eq.${orderId}` },
    (payload) => { /* update local state from payload.new */ })
  .subscribe();
```

**Deep link format:** `https://www.google.com/maps/dir/?api=1&destination={lat},{lng}` — use `point_a_lat/lng` while `accepted`, `point_b_lat/lng` while `picked_up`.

**Explicitly deferred, not part of this screen:** live "agent nearby" proximity alerts. `agent_location_pings` has zero rows ever written — no agent-side background location-pinging feature exists yet. Build this screen to work completely without it.

## RPCs to call (all via `supabase.rpc(...)`, never direct table writes — see grants note below)

```js
// Customer only — fetch raw OTP to read aloud
const { data: otp } = await supabase.rpc('get_pickup_otp', { p_order_id: orderId });

// Agent only — submit code, flips accepted → picked_up
const { data: ok } = await supabase.rpc('verify_pickup_otp', {
  p_order_id: orderId, p_submitted_otp: enteredCode
});

// Agent only — must succeed before seal check is possible. Requires status = 'picked_up'.
// One photo per order — a second call fails with "already submitted".
const { data: ok } = await supabase.rpc('submit_delivery_photo', {
  p_order_id: orderId, p_photo_url: uploadedUrl
});

// Customer only — 'intact' or 'broken'. Fails if no delivery_photos row exists yet.
// Flips picked_up → delivered. If 'broken', auto-inserts an open complaint.
const { data: ok } = await supabase.rpc('verify_delivery_seal', {
  p_order_id: orderId, p_seal_status: 'intact' // or 'broken'
});
```

All four RPCs independently re-check the caller's identity (`auth.uid()`) and the order's current state server-side — they don't trust the client to only call them at the right time, so handle the thrown exceptions (wrong person, wrong status, already done, etc.) as real user-facing errors, not edge cases to ignore.

## Schema reference

**`orders`** — `id`, `customer_id`, `status` (enum: `open`/`accepted`/`picked_up`/`delivered`/`cancelled`), `item_description`, `item_category`, `point_a_address`/`point_a_lat`/`point_a_lng`, `point_b_address`/`point_b_lat`/`point_b_lng`, `delivery_speed` (enum: `standard`/`express`/`super_fast`), `price_paise`, `accepted_agent_id`, `pricing_mode` (enum: `fixed`/`auction`), `min_bid_paise`, `photo_urls` (text array), `purchased_insurance`, `declared_value_paise`, `is_perishable`, `legal_attestation_confirmed`, `weight_kg`, `parcel_size`, `created_at`.

**`profiles`** — `id`, `first_name`, `last_name`, `date_of_birth`, `phone_number`, `address`, `landmark`, `occupation`, `avg_rating_as_agent`, `completed_deliveries_count`, `last_delivered_at`, `is_admin`, `is_business`, `company_name`, `business_registration_number`, `is_agent_verified`, **`avatar_url`** (new this session, nullable text).

**`agent_vehicles`** — `id`, `profile_id`, `vehicle_type` (enum: `bike`/`car`/`bus`/`other`/`none`), `registration_number`.

**`pickup_verifications`** — `order_id`, `otp_code`, `otp_verified_at`. Auto-generated by trigger on accept. Direct table access is revoked for `authenticated` — only the RPCs above touch it.

**`delivery_verifications`** — `order_id` (unique), `seal_status` (`intact`/`broken`), `verified_by`, `verified_at`. Written only via `verify_delivery_seal`.

**`delivery_photos`** — `order_id` (unique), `photo_url`, `uploaded_by`, `uploaded_at`. Written only via `submit_delivery_photo`.

**`complaints`** — `order_id`, `raised_by`, `reason`, `status` (enum: `open`/`investigating`/`resolved`/`dismissed`), `created_at`. Auto-inserted on a broken seal. Participants can manually raise one too (must self-attribute, must start `open`), but cannot edit or resolve their own — only `is_admin_user()` can transition status.

**`agent_location_pings`** — exists, RLS is set up, but nothing writes to it yet (0 rows ever). Not this screen's problem.

**`push_tokens`** — table exists, nothing sends to it yet (no edge function wired). Not this screen's problem either.

## Storage buckets

| Bucket | Public? | Folder convention | Who can upload | Who can view |
|---|---|---|---|---|
| `item-photos` | Yes | `{uploader_uid}/...` | Owner only, own folder | Anyone |
| `agent-documents` | No | `{owner_uid}/...` | Owner only, own folder | Owner only |
| `avatars` (new) | Yes | `{owner_uid}/...` | Owner only, own folder (insert + update/replace) | Anyone |
| `delivery-photos` (new) | No | `{order_id}/...` | Only the order's `accepted_agent_id`, only while `status = 'picked_up'` | Order participants + `is_admin_user()` |

## Design decisions locked this session (don't re-litigate)

- **Avatar:** built now (column + bucket), not deferred to a placeholder.
- **Contact button:** `tel:{phone_number}` link — chat isn't built yet, this is the interim.
- **Delivery verification:** photo proof only (not a second OTP). Agent submits photo → customer can then check seal → order completes. This ordering is enforced server-side, not just in the UI.
- **Broken seal:** order still flips to `delivered` (payment already happened outside the app) — a complaint is auto-raised for admin review instead of blocking the order.
- **Admin notification:** no push/email infra exists for admins yet — "notify admin" currently just means the row lands in `complaints` with `status = 'open'`, which the admin dashboard presumably already polls/queries. If it doesn't yet, that's a dashboard task, not a mobile app task.
